# Agent instructions

A build guide, firmware and docs for turning an IKEA KALLSUP speaker into a battery-powered Music Assistant speaker with an ESP32-S3 and an ESPHome config. This file is the single index for anyone, human or tool, changing the repo.

## Check

`make check` is the gate and what CI runs. It validates the ESPHome config (`esphome config firmware/kallsup-sendspin.yaml`, with a throwaway `secrets.yaml` and a generated key; needs `pip install esphome`) and checks that the generated pictures match their generators: `python3 tools/gen_diagram.py --check`, `python3 tools/gen_mockups.py --check` and `sh tools/brand/check-icon.sh` (needs pillow). CI also runs weekly, because ESPHome releases can change what validates. `make social` redraws the social card and needs Google Chrome.

## Layout

| Path | What lives there |
|---|---|
| `firmware/kallsup-sendspin.yaml` | the ESPHome config; `secrets.yaml.example` is its template |
| `docs/` | build guide, wiring, board notes, FAQ; index in `docs/README.md`; dated records in `docs/archive/` |
| `tools/` | diagram and mockup generators, photo annotator, vendored brand kit |
| `llms.txt` | one-page summary for search engines; keep it true |

Root holds only README, LICENSE, SECURITY, CONTRIBUTING, CHANGELOG, AGENTS (`.md`), `llms.txt` and config files.

## Do not change

Anything flashed to a device is a runtime identifier: GPIO assignments, entity names, the device name and the API and OTA settings. Renaming one orphans the device in Home Assistant or breaks the next flash. Changing a pin means the wiring docs and diagrams change in the same commit.

## Rules

- Documentation must be true of the code: every command, pin and measurement. Run a command before documenting it. No hand-typed counts that can drift.
- Commits are conventional (`fix:`, `feat:`, `docs:`, `refactor:`, `ci:`, `chore:`) and authored by the repo owner. No co-author trailers, session ids or "generated by" lines in commits, PRs, issues or comments.
- Never force-push `main` and never commit secrets, keys, tokens, IP addresses, private hostnames or personal e-mail. The one public contact address is caputodav@gmail.com. `firmware/secrets.yaml` stays git-ignored.
- Style: directories `lowercase-kebab`, Python `snake_case`, docs `docs/lowercase-kebab.md`. No em dashes in new copy.
- README keeps its shape: centered header, emoji `##` headings separated by `---`, the architecture diagram drawn by `tools/gen_diagram.py`, a repo tree that matches `git ls-files`, and the credit footer as the last line.

## Firmware and hardware notes

- **Hardware findings carry a status.** In `docs/board-notes.md` every finding is measured (✅), inferred (🔎) or open (🔍). Never promote one without a measurement, and never let the README or another doc state an inferred finding as fact. The three 🔍 build checks are marked 🔍 wherever they appear.
- **SendspinZero stays a pinned remote package.** Do not copy its YAML in. A `ref` bump is its own commit, validated with `esphome config`, and noted in `CHANGELOG.md`.
- **Keep the firmware locked down.** The API stays encrypted, OTA stays `encryption: {}`, the fallback hotspot keeps its password.
- **The firmware example is `secrets.yaml.example`**, following ESPHome's `secrets.yaml` convention; it carries `CHANGE_ME_KEY` on purpose and CI substitutes a generated key.
- **Photos** in `docs/assets/photos/` are resized to 1400 px and stripped of metadata before commit.
